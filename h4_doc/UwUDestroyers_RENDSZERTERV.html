2. Rendszertervezés (System Design Document)

Architektúra áttekintés

A rendszer háromrétegű architektúrát követ, amely elkülöníti a megjelenítési, üzleti logikai és adatkezelési feladatokat.

Réteges felépítés:

• Megjelenítési réteg (Presentation Layer) - React frontend alkalmazás

• Alkalmazási réteg (Application Layer) - ASP.NET Core API kontrollerek és szolgáltatások

• Adatkezelési réteg (Data Access Layer) - Entity Framework és MySQL adatbázis

Komponens-terv

Fő modulok és csomagok

Frontend modulok (React):

• components/ - Újrahasználható UI komponensek

• pages/ - Oldal komponensek (Főoldal, Receptek, Hűtő, Bevásárlólisták)

• services/ - API hívások kezelése

• context/ - Globális állapot kezelés

• utils/ - Segédfüggvények és kontrasztos mód implementáció

Backend modulok (ASP.NET Core):

• Controllers/ - REST API végpontok

• Services/ - Üzleti logika implementáció

• Models/ - Domain entitások és DTO-k

• Data/ - Adatbázis kontextus és migrációk

• Repositories/ - Adatbázis műveletek

• Helpers/ - Segédosztályok (pl. JWT kezelés)

Fő osztályok és felelősségeik

Osztály neve Felelősségek
User Felhasználói adatok tárolása, autentikáció és autorizáció, kapcsolatok kezelése
Recipe Recept adatok tárolása, hozzávalók és elkészítési lépések kezelése, kategóriák és címkék kezelése
Ingredient Hozzávaló alapadatok tárolása, kategorizálás és mértékegységek kezelése
Refrigerator Felhasználói hűtő tartalmának nyilvántartása, lejárati dátumok követése
ShoppingList Bevásárlólisták kezelése, tételek státuszának nyomon követése

Interakciós terv

Adatáramlás - Recept létrehozása

1. Frontend → RecipeController.CreateRecipe()

2. RecipeController → RecipeService.ValidateAndSave()

3. RecipeService → IngredientService.ValidateIngredients()

4. RecipeService → RecipeRepository.Save()

5. RecipeRepository → MySQL adatbázis

Adatáramlás - Hűtő tartalom ellenőrzése

1. Frontend → RefrigeratorController.GetAvailableIngredients()

2. RefrigeratorController → RecipeService.FindMatchingRecipes()

3. RecipeService → RefrigeratorService.GetCurrentItems()

4. RefrigeratorService → RefrigeratorRepository.FindByUser()

Adatáramlás - Bevásárlólista generálása

1. Frontend → ShoppingListController.GenerateFromRecipe()

2. ShoppingListController → RecipeService.GetMissingIngredients()

3. RecipeService → RefrigeratorService.CheckInventory()

4. ShoppingListService → ShoppingListRepository.Save()

Használt tervezési minták

MVC (Model-View-Controller):

• Frontend és backend elkülönítése

• Egységes architektúra a teljes alkalmazásban

Repository minta:

• Adatbázis műveletek egységes kezelése

• Üzleti logika és adatréteg elkülönítése

Service Layer minta:

• Üzleti logika centralizálása

• Kontrollerek vékonyan tartása

DTO (Data Transfer Object):

• Adatok biztonságos átvitele rétegek között

• Entity és prezentációs modell elkülönítése

Technológiai környezet

Frontend technológiák:

• React 18+ - Komponens alapú UI fejlesztés

• TypeScript - Típusbiztos JavaScript

• Axios - HTTP kliens

• React Router - Oldal navigáció

• Material-UI - Design rendszer

Backend technológiák:

• C# - Programozási nyelv

• ASP.NET Core - Alkalmazás keretrendszer

• Entity Framework Core - ORM megoldás

• JWT Bearer - Autentikáció

• Swashbuckle - API dokumentáció

Adatbázis:

• MySQL 8.0 - Relációs adatbázis

• Pomelo Entity Framework - MySQL provider

Egyéb technológiák:

• Docker - Konténerizáció

• xUnit - Unit tesztek

• Selenium - Integrációs tesztek

Külső interfészek, API-k

Belső REST API végpontok:

• /api/users - Felhasználói műveletek

• /api/recipes - Recept műveletek

• /api/ingredients - Hozzávaló műveletek

• /api/refrigerator - Hűtő műveletek

• /api/shopping-lists - Bevásárlólista műveletek

Külső API integrációk:

• Email service - Regisztráció megerősítéséhez

• Képfeltöltés service - Profilkép és recept képek tárolásához

Korlátozások, feltételezések

Technikai korlátozások:

• MySQL adatbázis használata kötelező

• Modern böngésző támogatás (Chrome, Firefox, Safari legújabb verziói)

• Internet kapcsolat szükséges (kivéve offline mód)

Teljesítmény feltételezések:

• Maximum 50-100 egyidejű felhasználó

• 10 000 recept tárolási kapacitás

• 2 másodperc alatti válaszidő

Biztonsági feltételezések:

• Jelszavak bcrypt titkosítással

• JWT token alapú autentikáció

• HTTPS kommunikáció
